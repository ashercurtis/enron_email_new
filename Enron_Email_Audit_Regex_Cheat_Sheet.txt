2. WORD BOUNDARIES AND ALTERNATIVES
\b(?:office|fax|mobile)\b
Find these whole words in the first email's business signature.
Compare with office|fax|mobile. Boundaries reduce fragment matches.
Every highlighted span is an occurrence; all spans here belong to ONE

3. MESSAGE ID
\AMessage-ID:\s*(?P<MessageID><[^>]+>)
\A anchors the beginning of the entire input. The named group captures
the supplied identifier, including angle brackets. [^>] means not >.

4. HEADER / BODY SPLIT WITH EXACT RECONSTRUCTION
(?s)\A(?P<EmailHeader>Message-ID:.*?\sDate:.*?\sFrom:.*?\sTo:.*?\s)(?P<EmailBody>Subject:.*)\Z
Inspect the two named groups. Their concatenation equals the original.
The first outer Subject: label starts EmailBody under this CASE convention.
Subject is normally a header field, but flattening prevents reliable
separation of subject text from newly written message text here.
.*? is lazy: it stops as soon as the next ordered label can match.

5. ALL OUTER METADATA, SAFELY BOUNDED BEFORE THE BODY
(?s)\AMessage-ID:\s*(?P<MessageID><[^>]+>)\s+Date:\s*(?P<DateRaw>.*?)\s+From:\s*(?P<FromRaw>.*?)\s+To:\s*(?P<ToRaw>.*?)\s+(?=Subject:)
This matches only the header prefix, stopping before Subject:.
(?=Subject:) checks the next characters without consuming them.
Named groups preserve raw fields. Forwarded From:/To:/Date: labels later
in the body do not supply these outer metadata values. The notebook
first splits the header, then extracts metadata exclusively from it.

6. OUTER DATE ONLY
(?s)\AMessage-ID:.*?\sDate:\s*(?P<DateRaw>.*?)\sFrom:
Capture the date as text; regex is not calendar validation. Python's
email.utils.parsedate_to_datetime will interpret the numeric offset.
Local sending hour and UTC ordering are distinct concepts.

7. OUTER SENDER ONLY — INCLUDING A DISPLAY NAME
(?s)\AMessage-ID:.*?\sDate:.*?\sFrom:\s*(?P<FromRaw>.*?)\sTo:
Try the synthetic example below. FromRaw should include
legal <.taylor@enron.com>, not the forwarded sender.

8. ADDRESS EXTRACTION — USE ON CAPTURED FromRaw OR ToRaw
[^\s<>;,]+@[^\s<>;,]+
Copy a raw field into Test String to demonstrate this second step.
It preserves unusual supplied spellings such as .taylor@enron.com.
This is lightweight extraction, not full email-address validation.
Applied to the entire email, it ALSO finds addresses in quoted threads,
signatures, and the Message-ID; those are not necessarily outer senders.

9. WORKED PHONE / ILLUSTRATIVE PII SCREEN
(?<!\w)(?:\+?1[ .-]?)?(?:\(\d{3}\)|\d{3})[ .-]\d{3}[ .-]\d{4}(?!\d)
Find common North American phone formats. The first email includes office,
fax, and mobile signature numbers. The original PII policy was not supplied;
phone numbers are an illustrative teaching category, not automatic violations.
Try appending this optional extension to the pattern:
(?:\s*(?:ext\.?|x)\s*\d{1,5})?
An extension can change the matched span without changing occurrence count.
Limitations: international formats, no separators, and obfuscated digits.

11. POSSIBLE CREDENTIAL DISCLOSURE CANDIDATES
\b(?:password|login|username)\s*(?:is\b|:|=)\s*\S+
Compare with 10. This adds a connector and a following non-whitespace token.
It can capture password is the, not an actual secret. Placeholder values,
instructions, and quoted text can match. Inspect surrounding text; do not
infer disclosure or authorization from a highlighted span. Disclosures
without these labels can be missed. Do not copy plausible real secrets.

12. BROAD EMPLOYMENT LANGUAGE
\b(?:interview\w*|recruit\w*|resume|job opportunit\w*|employment)\b
\w* allows endings such as interviews or interviewing. A match can concern
hiring someone else, a news interview, or unrelated quoted material.

13. ILLUSTRATIVE COMPETITOR NAMES

These are editable teaching assumptions, NOT an authoritative competitor

14. EMPLOYMENT AND AN ILLUSTRATIVE NAME IN ONE EMAIL
(?is)\A(?=.*\b(?:interview\w*|recruit\w*|resume|job opportunit\w*|employment)\b)(?=.*\b(?:Dynegy|Duke Energy|Reliant)\b).+\Z
Two positive lookaheads require both conditions anywhere in the input.
This highlights the WHOLE record once, not each employment occurrence.
In Python the notebook instead intersects the RecordIDs of two searches,
retaining employment occurrence counts. Co-occurrence can span unrelated
quoted messages. It does not establish an interview or policy violation.

15. OPTIONAL QUOTED-THREAD DELIMITER
(?i)-{2,}\s*Original Message\s*-{2,}|-{2,}\s*Forwarded by\b
Find recognized delimiters. Text before the first match is only a heuristic
and still includes the subject; it is not guaranteed newly authored text.
Default notebook searches use the full EmailBody for comparability.

16. OPTIONAL ATTACHMENT REFERENCE
<<\s*File:.*?>>
An attachment reference does not mean the CSV contains the attachment.
We can search the reference text, not inspect attachment contents.

17. OPTIONAL ENCODING-ARTIFACT SCREEN

The final alternative is equals followed by a literal space. It can occur
inside flattened split words. Do not blindly delete equals signs or decode

QUICK TOKEN REFERENCE
\b           word boundary (zero width)
\d / \s / \w digit / whitespace / word character
.            any character except newline (unless dotall s is enabled)
[^>]         one character other than >
* / + / ?    zero or more / one or more / optional
{3}          exactly three repetitions
.*?          lazy repetition
|            alternatives
(?:...)      group without capturing
(?P<Name>...) named capturing group (Python flavor)
(?=...)      positive lookahead: require what follows, consume nothing
(?<!\w)      negative lookbehind: preceding character cannot be a word char
\A / \Z      beginning / end of the entire input
(?i) / (?s)  ignore case / allow dot to include newline
Escape literal punctuation: \. matches a dot; . alone is a wildcard.
